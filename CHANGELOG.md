# Changelog

All notable decision milestones and project state changes.

## [architecture-slices] — 2026-08-13

### Internal

- **Image ▸ Flip Horizontal flipped one layer.** The entry sat in the Image menu, where Photoshop's entry of that name mirrors the whole canvas, and mirrored the active layer instead — so on a three-layer document one stroke moved and the others stayed, which reads as a bug rather than a feature. The layer flips moved to **Edit ▸ Transform**, which is where Photoshop keeps a layer flip.
- **Image ▸ Image Rotation** now carries what Photoshop puts there: 180°, 90° Clockwise, 90° Counter Clockwise, and canvas flips that mirror every layer at once. Rotation takes a quarter-turn count rather than being three separate commands, so 180° is one undo step and one document rebuild instead of two of each, and only an odd count swaps the canvas axes.

- **Select ▸ Modify asks how far.** The five modify entries are spelled with an ellipsis, which promises the user gets to say how much, and each applied the registry's default the instant it was clicked instead — a 2px expand, a 4px feather. For feather especially the radius *is* the operation, so a fixed one was close to useless. They open a radius prompt now, and the action's argument is the value the prompt opens on rather than the value it applies.
- **"Grow…" was the wrong name for Expand.** Photoshop has a Select ▸ Grow, and it extends a selection to neighbouring pixels of similar colour — nothing like a fixed dilation. The labels are Expand… and Contract…, and all five moved into a **Modify** submenu, which is where Photoshop keeps them and which leaves the Select menu's first screen to the five commands people actually reach for.

- **The status bar printed the zoom twice**, once in the document summary on the left and again four items to its right, in the cluster reserved for per-frame metrics. The duplicate is gone and a guard fails on any label there that reads a field the summary already states.

- **There was no way to zoom in or out.** An image editor with a zoom tool, a Navigator and a zoom readout in the status bar had no Zoom In, no Zoom Out and no 100% — one Zoom to Fit on `Ctrl+Shift+J`, which is not a zoom binding in any editor. The View menu now opens on the four Photoshop puts first: Zoom In (`Ctrl+=`), Zoom Out (`Ctrl+-`), Actual Pixels (`Ctrl+1`) and Fit on Screen (`Ctrl+0`).
- The steps walk a ladder rather than a multiplier, so zooming in and out again lands back on the number you started from and the ladder passes through 100% exactly instead of 99.6%. They anchor on the viewport centre, which needs no pan correction because the camera's pan *is* the world point drawn there; the wheel keeps anchoring on the pointer.
- **`+` could not be typed into a shortcut.** The chord parser split on `+` and dropped the key along with the empty pieces either side of it, so a user rebinding Zoom In to `Ctrl++` — the binding Photoshop prints — silently got a bare `Ctrl`, which Qt cannot activate and nothing reported. Two empty tails now mean the key is `+`; one is still a dangling separator.

- **Undoing a step deleted its row from the History panel.** The projection walked only the applied side of the timeline, so an undone edit left nothing to say what redo would bring back and nothing to click to get there — a history that only remembers where you stayed. Undone steps are listed now, dimmed above the cursor the way Photoshop greys the steps ahead of you, and clicking one walks *forward* to it: `history.jump` asks the applied side first and the redo side second, and carries the direction through to the host.
- The panel stops reading "Brush stroke · stroke". A row's kind is taxonomy rather than a name, and it now sits in the same muted trailing column the command palette uses for an action's menu.

- **Save As renamed the window title and left the tab reading "Untitled".** A tab's label and dirty dot are `document_name` and `dirty` — the two values the title binds to — but they reach QML as a pushed JSON string rather than as those properties, so the strip went stale wherever a caller re-emitted the properties and forgot it. Saving also left the dirty dot on. The push now sits inside `emit_doc_fields`, which every such caller already goes through, and `the_tab_strip_is_refreshed_with_the_document_fields` fails if it is taken back out.
- **Scroll bars are themed.** The Basic style draws its handle in `palette.mid` and, under `AlwaysOn`, leaves a hairline track behind it — a pale grey blob on a white rule, which in the Preferences dialog ran straight down through the UI-density combo box and the history-retention spin box. `ThemedScrollBar` is a quiet overlay bar that thickens under the pointer, and the two surfaces that pin theirs on now reserve its width instead of letting the handle land on the control beneath it.

- **Every file chooser reopened where it was built, not where the user was.** Each `FileDialog` keeps its own `currentFolder`, so Open, Save As, Export and Embed ICC each remembered somewhere different and all four were pinned to Pictures by a declared binding: saving into `~/work` and then pressing Ctrl+O landed back in Pictures. One policy now serves all four — the open document's folder first, then the folder any chooser was last accepted in — assigned before `open()` rather than bound, because a live binding would drag the user back out of a folder they had just navigated into. `every_file_dialog_opens_where_the_user_last_was` fails the build on a direct `someFileDialog.open()`.
- **Five dialogs still carried Basic-style buttons**, including About, Preferences, the compatibility report and the recovery chooser. They set `Dialog.standardButtons`, which builds its buttons from the Controls style, so a dialog that never writes a button down ships light ones however carefully the rest of it is themed — the sweep that converted every bare `Button` could not see them. `ThemedDialogFooter` is a `DialogButtonBox` with a themed delegate and a transparent strip, and `standardButtons` forwards to it, so each dialog changed one line. It right-aligns rather than stretching, because a button box left to fill the row hands a two-button dialog two half-width slabs.
- The unsaved-changes prompt writes its three buttons out instead: `standardButtons` cannot say that saving is the commit and discarding is destructive.

- **Adding a layer painted the whole canvas red.** Layer textures were allocated from a rotating eight-colour palette — scaffolding from when the compositor was being built and an empty stack had to be visible to work on. Nothing ever writes over a layer that has no pixels, so that clear colour *was* what an empty layer composited as: a new document opened onto two coloured rectangles rather than a page, the second added layer arrived as translucent red over the image, and an empty layer came back coloured after a save and reopen because the `.ptx` carried no raster to overwrite it with. Every kind now clears to transparent; `LayerKind::Fill` keeps its colour, which is document data rather than a starting point.
- A new document is white instead. Photoshop's File › New starts on an opaque white Background, and a canvas that is transparent all the way down reads as "nothing here" against the checkerboard while every first stroke, fill and flatten composites against nothing. The white is written into the bottom layer once by the host, before the document is handed over — it belongs to the pixels, not to the graph, which owns no buffers — so it is part of the initial state rather than an undoable step, and it saves and reopens like any other raster.
- `adding_an_empty_layer_changes_no_pixel` holds the line, device-backed under `--features gpu-tests`. Verified by putting one palette colour back and watching it fail.

- **Baking text could not be undone**, which is the third command in the family found writing a kind change and a payload clear straight onto the graph with no history entry — after rasterizing a shape and rasterizing a smart object. Each discards the only copy of something a user cannot recreate: a layer's words, a shape's editable path, a smart object's original pixels. Two lines of help text around the Bake Text button had grown up around the defect, one of them advising the reader to leave the panel rather than press it; they are gone, and the button says undo brings the text back.
- `every_conversion_to_pixels_can_be_undone` covers all three from one table — a fourth conversion has somewhere obvious to be added and fails there if it forgets. Verified by removing a history push and watching it fail.

- **The transform tool silently threw away its own work on a smart object.** It baked the committed draft into the pixels while the placement went on saying something else, so the next nudge of the scale slider restored the source and discarded the transform. A commit on a smart object now folds into the placement instead: rotations add, scales multiply, offsets sum, and the result is applied to the pristine source — so a move, then a scale, comes back at full quality with both intact.

- **Two documents open, both with a smart object, and the second showed the first one's pixels.** Layer ids restart at 1 in every graph, and the host held one map of smart-object sources across every open tab — so a second document's smart object at layer 3 read, displayed and *saved* the first document's source. Sources park and unpark with their document now, for the same reason the parked layer pixels already do, and closing a tab drops them: nothing did before, and each one is a whole document of pixels.
- **Rasterizing a smart object threw its source away, and rasterizing is undoable.** The undo put the kind and the payload back and the panel then described a source that no longer existed. A source now lives as long as its document, the way history holds the layer payloads it may need to put back.
- **Rasterizing a shape could not be undone at all.** It wrote the kind and the payload straight onto the graph and pushed no history entry, so discarding a shape's editable path — the only copy of it — was permanent. The kind and the payload go into history as one entry, like a smart object's.

- **Menus are themed.** The menu bar, every drop-down and every context menu were the last of the Basic style left in the shell: a light strip and light popups opening out of dark editor chrome. `ThemedMenu` and `ThemedMenuItem` draw them from `Theme.qml` — a marker column holding either the item's icon or its check mark so labels line up down the menu, the shortcut chord right-aligned in mono rather than after a literal tab character, and a submenu caret. A comment on the menu bar had claimed Fusion paints it and ignores custom backgrounds; the shell links only the Basic style plugin, which honours both, so the bar had been shipping light on the strength of a style it does not run.
- Drawing a menu row by hand means owning what the style used to do: `Theme.withoutMnemonic` strips the accelerator markers the action registry writes, or the bar reads "&File &Edit &Image".
- **Five colour tokens had the wrong byte order.** Qt parses an eight-digit hex colour as `#AARRGGBB`; CSS parses it as `#RRGGBBAA`, and that is how they were written. The accent washes — the active tool, the selected panel tab, every highlight — had been drawing a pale green at a quarter opacity rather than the accent, and `scrimModal` (`#000000B8`, meaning black at 72%) parsed as alpha `0x00`, so **modal dialogs had no scrim at all**.
- The unstyled-control guard now reads inline declarations too. `delegate: MenuItem {` is not at the start of a line, which is how the layer context menu kept its light popup through a sweep that converted every other menu — and how a slider in the layer-styles colour editor kept the Basic style through the sweep before it.

- **A polish pass over the right dock, on a clean profile.** Every earlier check had run on a developer home directory with a Qt style configured system-wide, which is not the profile any user has; running with an isolated home is what surfaced most of this.
- Sliders and text fields join the themed set. The Basic style's slider is a bright blue groove under a large white disc — taller than the rows it sits in and the loudest thing in a panel of muted chrome, eighteen times over. `ThemedSlider` is a thin groove with a small accent handle so a column of them reads as a column; `ThemedTextField` is sunken like `ThemedSpinBox`, which is what distinguishes a field you type into from a button at a glance. The Swatches hex field and the Layers lock buttons drop their private copies of that styling.
- **The Properties panel clipped a heading mid-word with no cue that it scrolled.** The scroll bar is pinned on whenever there is more than fits, the cut edge fades, and the panel body reserves the bar's width at the right margin — it had been drawing over the border of every full-width button.
- Three sections opened with a row repeating their own group title: "Fill" under *Fill*, "Character" under *Character*, and "Free Transform" under a button reading *Free Transform*. Each was a row of the panel with the least height to spend on it.
- Focus rings on buttons, tabs and the paint-target chips follow `visualFocus` rather than `activeFocus`, so clicking one no longer leaves a keyboard-focus ring behind on a control that is no longer current.

- **Smart objects.** Transforming a raster layer bakes: scaling to a tenth and back gives you a twenty-times upscale of whatever survived. `LayerKind::SmartObject` keeps the pixels the layer was made from and re-applies its placement to *those* — restore the source, apply the whole transform, never compose one placement with the last — so a round trip through 5% comes back exactly as sharp as it went in. It was the one non-destructive primitive the application had no form of ([DR-032](internal_docs/Appendix/Decision-Register.md)).
- The source is not in the graph. The engine describes documents and owns no pixel buffers, so `SmartObjectContent` carries the source's name, dimensions and placement, the host holds the pixels by layer id, and `.ptx` gains an optional `SRCE` chunk with a `smart_asset_ids` map — the same shape the mask chunk was added in. `RASL` and `SRCE` for one layer are deliberately different pictures: the raster is what is on screen, which for a smart object is the placed result. Both families now allocate from one id space with a test holding them apart, because the assets come back in one flat map and a collision would let one silently replace the other.
- Wrapping and rasterizing each change the layer's kind *and* its payload, and both go into history as one entry. A graph where one has been undone and the other has not is a smart object with no source, or a raster layer carrying one, and every reader of the payload would have to guess.
- Only a pixel layer can be wrapped. A group, text, shape, adjustment or fill layer describes itself rather than owning a buffer, so there is nothing to capture, and the command says so rather than wrapping an empty source. Linked sources, editing contents as a sub-document, and smart filters are deferred by the DR, not silently missing.
- One ordering bug found by looking at it: the source was stored *after* the command, and invoking a command republishes the inspector projection — so the panel's first look at a brand new smart object reported its original pixels missing.
- A new guard found a second, older one. `action_enablement` ends in a catch-all that falls back to "a document is open", so an action naming a tag the host does not answer is not an error — it quietly becomes enabled whenever anything is open. `action.app.recover-gpu` had been declaring `document` instead of `has_document` since it was written. The arms are read out of the host as text now and compared against every action's tag.

- **Every push button in the shell was a white rectangle on a clean profile.** No Qt Quick Controls style is configured, so the shell runs the Basic style, whose palette is hardcoded light and ignores `palette` — which is why the check boxes, combo boxes and spin boxes already had themed replacements. Buttons never got one. The defect was invisible on a developer profile with a Qt style set system-wide and obvious on a fresh home directory, which is the profile every user has; it survived in thirty-seven places while four call sites hand-wrote the same rounded rectangle and label to work around it.
- `ThemedButton` is the one home for that treatment, with a `prominence` of `normal`, `primary` or `danger` and `flat` for a run of secondary actions. The New Document dialog's Cancel and Create, and the recovery chooser's Discard and Discard All, lost their private copies of it and say what they are instead. `no_unstyled_controls_reach_the_user` now fails the build on a bare `Button`, `CheckBox`, `ComboBox` or `SpinBox` anywhere in `qml/` — verified by putting one back and watching it fail.

- **A shape layer's fill and stroke can be edited.** They have always been on the layer and have never had an editor, so a shape created from the Layer menu was the preset blue it was born with for good — the same shape as the adjustment sliders that named three kinds and left four unreachable. The Properties panel's new Shape section carries both colours, the stroke width, the two on/off toggles and a read-only W/H/X/Y for the box the path's anchors occupy. That readout is arithmetic on data the engine already holds; a raster layer's extent is a GPU readback and could not be published on every sync, which is why only shapes get one.
- The five values are a `ShapeAppearance` read and written as one thing, and `shape.set-appearance` replaces them without touching the geometry. Undo restores the whole payload in one entry rather than five parameter deltas that could be replayed out of order against a path edited in between. Values clamp on the way in — colour channels to `0..=1`, stroke width to `0..=512`, a non-finite width to zero, since a NaN reaching the rasterizer produces a shape with no pixels and no explanation.
- Recolouring to the value already stored is refused, or a slider release that moved nothing would push a history entry. A shape with neither a fill nor a stroke is allowed: Photoshop allows it, and refusing it would also refuse the moment between turning one off and the other on. The panel says so instead.
- A hex field re-reads the document when focus leaves it, not only when the value changes. `Ctrl+Z` inside a text field is the *field's* undo, so a field that keeps focus through an undo shows a value the document no longer has.

- **Properties is a contextual panel now, the way Photoshop's is.** It described everything at once — a brush size above a text frame above a soft-proof profile — because every section carried its own visibility rule, and several of those rules compared a layer kind against a string literal written into QML. That is the layer vocabulary written a second time in a language with nothing to check it: renaming a kind, or adding one, changes nothing except which sections silently stop appearing. Presence is now decided by *subject* — the document, or one of the six layer kinds — declared once per section in the engine's disclosure descriptors, and a test reads the panel as text and fails when the two disagree on which sections exist, their order, or their titles.
- Four control clusters left the panel, each to the home it already had. Brush size, hardness and texture, and the selection combine modes, were duplicates of the tool options bar; Fit and 100% were duplicates of its zoom field; the foreground R/G/B sliders were a third way to set a colour the Swatches panel already offers as wells, a hex field, a palette and a recents row. The brush *presets* had no second home, so they moved to the options bar as a picker, which is where Photoshop's preset well lives. Properties is about the selection; the options bar is about the tool.
- Four sections arrived. **Document** (canvas size, layer count, selection extent, file path, and quick actions for crop, rotate, flip and zoom) and **Guides and Grid** are what Photoshop shows when nothing is selected; PhotoTux always has an active layer, so the panel offers a Layer/Document scope switch instead of requiring a state the engine cannot reach. Selecting a layer returns to the Layer scope, because selecting something means you want to see it. **Align and Distribute** is in Properties as well as the Move tool's options bar, as it is in Photoshop, and is reachable there whatever tool is in hand. **Masks** was a bare column at the foot of the panel with no header, so four attribute sliders read as loose controls belonging to whatever was above them; it is a section now, with an empty state that offers to add a mask rather than simply not being there.
- **"Edit target" is gone.** It was a block naming a concept that exists nowhere else in the application, with a four-part summary line restating what the layers panel and status bar already show, above two buttons offered even for a layer with no mask — a choice with one legal answer. Photoshop needs no such control because the layer and mask thumbnails *are* the selector and the ringed one is the target. Properties now leads with the same thing: the layer's glyph and, when there is a mask, an `M` chip beside it, ringed like the layers panel's, with one line saying which of the two a stroke would land on. Without a mask there are no chips.
- The subject's name and glyph are resolved from the subject *being shown*, not from the live selection — found by shipping it the other way round for an hour and watching the Document tab wear the raster layer's icon, because a layer is still active while the document scope is open.
- One layout defect fixed on the way: a `ColumnLayout` nested in a `ColumnLayout` fills its height by default, so in a dock taller than the panel's content the header and every disclosure group shared out the slack and the scope tabs floated fifty pixels down the panel. Groups are pinned to their content and a spacer at the foot takes the leftovers. The old panel never showed this because it never had slack.
- The selection-outside-canvas badge moved from `inspector.selection` to `inspector.document`: the marquee's combine mode is a tool option, so there is no selection section to badge, and a marquee dragged off the canvas is a fact about the canvas.

- **The Navigator draws the document.** Its whole purpose is to say where in the image the viewport is, and it drew a flat rectangle — telling the user where they were relative to nothing. The composite is read back, downsampled with a box filter (nearest-neighbour makes a summary that flickers as the stride lands on different pixels), encoded as a PNG and handed to QML as a `data:` URL. That URL is the only route from Rust-held pixels into a QML `Image` here: the canvas is a native wgpu item, and a `QQuickImageProvider` would mean hand-written C++, which the crate boundaries keep out of everything but `phototux_canvas`. Base64 is written out rather than depended on — twenty lines against a fixed standard, held to the RFC 4648 vectors.
- Two guards, both needed: the rebuild happens only when the composite generation has changed *and* 600 ms have passed, since the generation alone would rebuild on every dab of a stroke and the clock alone would rebuild a document nobody is editing. It runs from the engine poll tick rather than the composite, because a full readback is thirty-odd megabytes at 4K and does not belong on the path DR-017 budgets.
- Two traps found by falling into them: the readiness test asks the canvas rather than the host's `has_document` field, which is synced *after* the composite a new document triggers and so still says "nothing to draw" on the first pass; and the QML side tests the string's length rather than `source != ""`, because assigning to a `url` property normalises the value and the comparison then says nothing useful.
- **Dock panels can be resized.** Every panel's height was a constant in the shell, so Properties was permanently capped at a fraction of the dock and its longer groups could only be scrolled. The seam between two stacked panels is draggable now, and the height is remembered in the dock topology — absent for a panel never dragged, since absent means "the shell decides" and writing a default for every panel would freeze a layout decision the shell should stay free to change. Undocking forgets a height, and Reset Workspace clears them all by replacing the topology, which is why there is no separate command for it.
- Two things had to be got right, both found by getting them wrong. A resized body must pin `Layout.minimumHeight` to its preferred height: once a panel is dragged taller the stack's preferred sizes exceed the dock, and a `GridLayout` resolves that by compressing whatever has no minimum, so the panel springs straight back. And a binding that resolves a height by *calling a helper* which reads a `var` property does not reliably re-evaluate when that property is reassigned — the drag reported the right numbers the whole way while the panel stayed put. An int revision bumped on every change, read by each binding, is the dependency that cannot be missed.
- The commit is computed from the pointer position at release rather than from the last preview, because motion events are not guaranteed: a fast drag, or a compositor that coalesces them, can deliver one or none, and a resize that depends on having seen them commits the height it started with.
- **Messages are toasts now, stacked bottom-centre over the canvas, and the status bar carries only state.** The two had been sharing one string: the status bar shows the document summary — size, zoom, active layer, tool — which is refreshed from six places, so a message was silently erased by the next refresh and only ever seen by someone already looking at the footer. Eighty-two message sites moved to a `notify` channel; a test now fails if anything but the summary is assigned to `status_text`.
- Severity is a `NoticeLevel` vocabulary rather than something the presenter infers from the text — guessing "error" from the word "failed" is the same mistake as classifying a typed error by grepping its `Display`. Info and warning fade after three seconds; **errors do not fade**, because a save that did not happen must not scroll past while the user is looking at the canvas. Every toast has a close button, and hovering holds one open, since a message worth reading is often longer than three seconds' worth of reading.
- A repeat counts up in place rather than stacking, so one refused command clicked four times does not become a wall, and the queue is bounded at four. Toasts are announced as alerts, with the severity spoken rather than left to the colour.
- Making messages reliable immediately exposed one that had always been posted and always swallowed: the composite runs from a timer and can fire before the GPU side of a document exists, so every launch was reporting a failed composite that the status bar overwrote before anyone saw it. The host asks `phototux_canvas::has_document()` now instead of inferring it from the error text — and the canvas's own guard against entry points bypassing `with_document` caught the new predicate, which is a named exception because a predicate must not run a device check as a side effect of being asked.
- Several messages were reclassified while passing through. "Copy mask failed: no active layer" is a warning that fades, not a sticky error — nothing failed, the user simply has to pick a layer — and it now says "Select a layer first."
- **Fourteen of the shell's twenty-one sliders had no accessible name.** Qt names a control from its visible text, and a slider has none — its label sits in a separate `Label` beside it with nothing connecting the two — so brush size, mask feather, the three foreground channels and the rest all reached assistive technology as an anonymous "slider". They are named now, with the current value where the value is the point ("Brush size, 12 pixels"), since someone adjusting a slider by ear needs the reading and not just the name.
- `qml/` has no test runner, so a new `chrome_contract` module reads the shell as text and fails when a `Slider` or icon-only button carries no name — the same approach the engine uses for icon packaging and menu structure. Verified by deleting a name and watching it fail.
- **Every layer row carried a blank bordered square.** It is a kind badge — G for group, T for text, A for adjustment — and it was empty for raster layers, which is most of them, so the panel showed what read as a thumbnail that had failed to load beside each ordinary layer. The slot is hidden when there is nothing to mark, which turns the badge into information: it means "this is not an ordinary raster layer".
- The letters were a nested conditional in QML over five kind strings — the layer vocabulary written a second time, where a sixth kind would have arrived as a blank badge indistinguishable from raster. They come from `LayerKind::badge` now, with a test asserting raster is the only unbadged kind and that no two kinds share a badge or a label.
- Adding those fields exposed a nastier trap, by falling into it: the layer row is written out in *three* places, and a delegate whose `required property` names a role the model lacks makes Qt abort the delegate — so the panel renders nothing, with no warning in the log and no visible cause. There was a guard, but it compared the model's roles against a literal list, which is a third copy that agrees with the model and says nothing about the panel. It now compares `role_names()` against the `required property` names scanned out of the delegate: both sides derived, equality in both directions, since a role the panel never reads is dead weight crossing the boundary. That immediately found one — `kind` itself, whose only reader the badge had replaced.
- **Empty dock panels were blank rectangles.** The History panel rendered nothing at all until the first edit, and the Layers panel showed a blend combo, an opacity slider and three lock buttons above an empty list when no document was open — chrome for a layer that is not there. Both have placeholders now, naming what will fill them, and the Layers control strip is hidden rather than disabled. History carries two, because the guidance differs by cause: with no document there is nothing to have a history of, and with one open the list simply has not been written to yet.
- The icon-packaging test only ever covered stems the *engine* declares, so a glyph written into QML by hand shipped blank with nothing to say so. It scans `qml/` for `iconKey:` and `iconUrl("…")` literals now — verified by deleting an entry from the qrc and watching it fail, rather than by trusting a green run.
- **Two Window-menu entries toggled panels that do not exist.** `panel.paths` and `panel.character` were declared by the engine, offered as Window-menu toggles, and rendered by no dock — so choosing one changed the persisted workspace and put nothing on screen, with no feedback of any kind. Their content has always lived as the Path and Character disclosure groups in Properties. The two descriptors are gone, and a test now reads `Main.qml` for the `panelShowsInDock` call naming each declared panel, so a panel cannot be declared without being drawn.
- The Window menu's panel toggles are generated from the panel vocabulary rather than written out beside it — seven hand-written entries restating `default_panels()`, two of them wrong. The shell routes them by id prefix now, too: it had carried a comment reading "a new panel needs no case of its own" directly above seven such cases.
- **Command failures were being classified by grepping their own error message.** The host called `to_string()` on a typed `CommandError` and then searched the result for the word "rejected" to decide whether it belonged in the status bar or down the diagnostic path — throwing away the value that already knew, and mis-routing anything else whose text happened to contain the word, which driver messages do. `CommandError::is_user_correctable` is a variant test now, and the callers pass the error rather than its rendering.
- Eleven more command call sites were still routing their failures through the *device* path — `report_gpu("add group", …)` and its like — which prefixed "failed:", ran the device-lost substring check on text that can never name a device, and printed to stderr as though a rejection were a diagnostic. All fourteen use the typed path now, and `report_gpu` says in its own doc comment what belongs there.
- The status bar also read like a log: "command rejected: layers already aligned". `user_message` renders the sentence instead — "Those layers are already aligned." — with the `command rejected:` framing left on `Display`, where logs and `Debug` want it. There is deliberately no table mapping internal reasons to friendly ones, because a second table is a second vocabulary and it would drift: the reason string *is* the message, and the reasons a user can actually reach are written as advice ("select a layer first", "this layer's position is locked — unlock it to move it"). Guards the enablement layer already prevents stay terse. A sweep over the shipped command registry asserts every reason survives presentation, so one added later gets the same treatment without anyone remembering.
- **Blend mode, opacity and the locks moved to the top of the Layers panel**, where Photoshop keeps them. They are the most-used control cluster in the application — the one a user reaches for without looking — and they had been living in Properties, three panels away from the layer they act on. That also gave back a fifth of the height budget of the one panel that has the least of it. The combo's drop-down gained a width floor in the process: squeezed into half a row it was narrower than its own longest labels, and a list that elides to "Pass Thro…" and "Darker Col…" is a list you cannot read.
- **The tool shelf is Photoshop's, slot for slot.** Twenty-five tools now live in eighteen buttons: tools that answer the same question share a slot — the two marquees, the two lassos, the wand and colour range, the bucket and the gradient, blur/sharpen/smudge, dodge/burn/sponge — and a slot shows the tool in use or last picked, marks itself with a corner wedge, and opens a flyout on right-click or press-and-hold. The rail order matches Photoshop's, which meant moving the polygonal lasso up next to the freehand one: it had sat two slots below with the wand between, so the pair a user thinks of as one tool were not neighbours and could not share a slot.
- That also fixes an overflow. Twenty-five buttons need about a thousand pixels of column and a maximized 1080p window leaves about nine hundred, so the tail fell into a "…" menu — a worse home for a tool than a flyout, since nothing about "…" says what is behind it. And the overflow button's own space was being reserved unconditionally, which *created* overflow at the boundary: a shelf with room for exactly every slot lost its last one to a menu, to make room for the button that menu needed. It is reserved only when it will exist.

The six selection tools are one band drawn as three slots. Splitting painting from retouching would have drawn a line through the middle of a block Photoshop leaves whole, so the retouch tools joined the paint band.

The list is now a capped, scrollable view showing a whole number of rows — measured from the content rather than guessed, since a guessed row height leaves the last row sliced in half and reads as broken rather than scrollable — with the scrollbar pinned on whenever there is more than fits, because five rows out of twenty-three with no scrollbar reads as "eighteen are missing".
- Every row in that chooser also read `Untitled (00000000)`. The label took the first eight characters of `document_id`, which is a zero-padded 128-bit value built from nanoseconds since the epoch xored with the pid shifted left 64 — nanoseconds occupy the low 64 bits and a pid maybe 22 more, so the top 32 bits are structurally zero for every document that will ever exist. `RecoveryEntry::short_id` reads from the end, and the row leads with the *saved time*, which is what actually tells two untitled snapshots apart.

It arms on the first press and deletes on the second, naming the count — a second modal stacked on the first is worse than confirming in place, and moving the pointer away disarms it so an armed button cannot be triggered later by a click aimed at something else.
- **Align and Distribute are two labelled runs in the Move options bar**, separated the way Photoshop separates them, rather than eight unlabelled icons in a row. They answer different questions and need different numbers of layers, and a dimmed distribute button now says in its tooltip how many layers it wants instead of being a dead end.
- **Blend If.** A layer can now be hidden where it is too dark or too light, and where the composite *underneath* it is too dark or too light — the cheapest way in the editor to knock a sky out of a photograph or confine a texture to the shadows beneath it. Each of the two ranges carries four stops rather than two, because a two-stop range is a hard cut whose edge is aliased and obvious; the inner pair are Photoshop's split slider handles. A range whose stops coincide is still a hard cut, so nothing is lost by always carrying four.
- The two ends break their boundary tie in *opposite* directions, which is the whole behaviour at a coincident pair — and coincident is the common case, since an unsplit handle is two stops on the same value and a full range is two of those. A pixel sitting exactly on a threshold is shown, at both ends. The first attempt wrote one ramp and used its complement for the other, and the test that catches it is the one asserting a range that hides nothing shows pure black and pure white: with the tie broken one way the default range hid black, with it broken the other it hid white, and either would have been invisible on every layer whose *other* range was untouched.
- `BlendIf::coverage` is the CPU reference the WGSL mirrors, held together by a device fixture that composites a tonal ramp over a tonal ramp so every stop is exercised somewhere in the frame — and that asserts each case actually changes the picture, since a case that changed nothing would pass the comparison while proving the shader never read the range. Coverage scales the source's contribution the way opacity does, so it multiplies into the same number; a layer whose ranges hide nothing reports channel `0` and costs no branch. The new uniform members are `vec4`s, so a layout test pins their sixteen-byte alignment: get it wrong and the shader still compiles and runs, reading the wrong words.
- Blend If costs about 30 µs on the 10×4K composite budget — measured, not assumed: the branch is the whole cost, and widening the layer uniform came out as noise. Worth recording separately is that the same machine measures 1.998 ms with the feature absent entirely, so DR-017's 2 ms gate has almost no real headroom left independently of this slice. The layer uniform's channel word rides in what was already padding, since that struct is read once per layer per pixel.

The command is declared *and implemented* as mergeable, so a handle drag is one history entry. The panel group is level 3 and closed by default: eight handles would dominate Properties, and this is not the first control anyone reaches for.
- **Align and distribute.** Six alignments and two distributions, under Layer > Align and Layer > Distribute where Photoshop files them, with the same eight buttons in the Move tool's options bar. Aligning layer *rectangles* would have been a no-op — every raster layer is document-sized, so every rectangle is the same one — so a target's edges are the bounding box of its non-transparent pixels, placed into the document by its transform. Measuring needs pixels and pixels live on the GPU, so the host measures and the engine decides: which frame to align to, how many targets an operation needs, and how the spacing works are all in `phototux_engine::align`, testable without a device.
- One layer aligns to the canvas and two or more align to their union, because aligning a single layer to its own bounding box does nothing. Distribution needs three and spaces *centres*, so boxes of different sizes land on an even rhythm rather than an even gap that looks uneven. A group is one target carrying every member: the compositor does not pass a group's transform to its children, so a group moves only by moving each member the same amount — and counting the members separately would spread them out instead of moving the group.
- The move is a translation, not a bake. The composite already honours `layer.transform`, so aligning stays non-destructive and one `SetTransform` batch is one undo entry however many layers moved. Offsets under a twentieth of a pixel are dropped, so realigning already-aligned layers is refused rather than stacking a no-op the user then has to undo; a position-locked target refuses the whole operation, since a partial alignment reads as a broken one.

The first attempt got the corner walk wrong and produced anchors sitting exactly on the square corners — caught by asserting that a rounded rectangle has actually lost its corners rather than that it merely has more points.
- **Seven retouch tools: clone stamp, dodge, burn, sponge, blur, sharpen and smudge.** They are all the same brush with a different `DabMode` — what a dab *does* — replacing the `eraser: bool` that was two states for a question with nine answers. `DabMode` owns each mode's tool id, title, icon and accelerator, so the tool rail is generated from the mode list and a mode cannot arrive with no way to pick it.
- Every retouch mode answers with a target colour at alpha = coverage, and the pipeline's ordinary alpha blend moves the pixel toward it, so one shape covers all seven and matches the CPU reference's `blend_toward`. Retouching never adds alpha: a transparent pixel has nothing to rework.
- The four modes that read pixels other than the one they write — blur, sharpen, smudge, clone — sample a **copy** of the layer rather than the layer itself. A pass may not read its own target, and even where the hardware allowed it a dab would feed on its own output and a blur would keep blurring what it had already blurred. The copy is taken once per batch, so a stroke still builds up across input events. A source-reading mode with no snapshot declines rather than guessing.
- A clone's offset is fixed when the stroke *begins*, from the alt-clicked anchor: recomputing it per dab would make the copy chase the cursor rather than stay aligned with the original.
- **The paint gate named two tool ids**, so all seven retouch tools were silently refused the moment they existed — `stroke_begin` returned early for anything that was not the brush or the eraser. It asks `DabMode::is_dab_tool` now. The device suite caught the other half: `target` is a reserved word in WGSL, so the stamp shader failed to compile outright.

- **Magic Wand and Colour Range.** One algorithm with a `contiguous` flag: the wand floods from the seed and stops at the tolerance boundary, colour range takes every matching pixel in the layer. It lives in `phototux_engine`, which has no wgpu, so the host reads the layer's pixels, calls it, and combines the R8 coverage into the mask through a new `SelectionMask::apply_coverage` — the engine owns which pixels belong together, the GPU crate owns how to move them. The flood uses an explicit stack: a 4K layer is sixteen million pixels deep in the worst case, which no call stack survives. - **Selection gained Smooth and Border**, and the Select menu is generated from `SelectionModifyOp` rather than restated. The conformance test that refuses an op no action can invoke fired the moment the two were added — three hand-written entries against a five-op vocabulary — which is exactly what it is for.

The generated ids reproduce the hand-written ones exactly, asserted literally, because a renamed action id drops a user's custom shortcut for it without saying so.

A small builder names only what an action actually has. `actions.rs` went from 1,690 lines to about 1,300, workspace duplication from 4.2% to 3.0%, and duplicated blocks from 134 to 59. The `#[expect(clippy::too_many_arguments)]` that covered the old signature reported itself as unfulfilled and was removed, which is what that attribute is for.

Every row that could be generated from a vocabulary now is; contorting the rest would make it less readable, not less duplicated.
- **Every layer style has been rendering with the wrong parameters.** `EffectPass` held one uniform buffer and rewrote it per pass through `Queue::write_buffer` — whose writes are staged until the encoder is submitted, so every pass recorded into one encoder read whichever uniform was written last. This is the same defect `SeparableBlur` was fixed for, in the same crate, and it was still here: the drop shadow's two passes both ran with the second one's parameters, the stroke's likewise, and two styles on one layer overwrote each other outright. Each pass owns its uniform now, mapped in at creation. It surfaced only when a device fixture asked every style to change the picture, which is what a test that iterates a vocabulary buys over a test that names one case.
- **Four new layer styles: Inner Shadow, Inner Glow, Gradient Overlay and Bevel.** Inner shadow and inner glow blur the layer's *un*covered area and clip it to coverage, so the darkness hugs the inside of the edge; a glow is an inner shadow at zero offset, the same relationship the outer pair have. The stroke gained a position — outside, inside or centre — defaulting to outside so documents written before the field keep the outline they were drawn with; the pass computes a dilation and an erosion of the alpha and takes the band each position names.
- **`style.add-drop-shadow` and its three siblings became `style.add`.** One command per style meant a new style needed a constant, a router arm, a handler, a taxonomy row and a hand-written action before it could exist — which is why the set stood at four. The Layer Style submenu is generated from `LayerStyle::ALL_KINDS`, with kind keys chosen so the four action ids that shipped are reproduced exactly: a renamed action id would drop a user's custom shortcut for it without saying so, and a test asserts those four ids still exist. Four `add*Style` slots on the session turned out to be dead already.
- **Layer styles have an editor.** They could be added from the menu and never changed — no control anywhere touched a colour, offset, radius or angle, so every style rendered at its defaults for good. That was already true of the four that shipped and would have been true of eight. Each style now declares its own scalar slots and colour labels the way adjustments and filters do, `layer_styles_json` projects the active layer through both, and the Properties panel builds one control per declaration while naming no style kind. `style.set-params` is declared mergeable *and implemented* as such, so a slider drag is one history entry rather than one per step; `style.set-color`, `style.set-enabled` and `style.remove` are discrete, and all four share a body because they differ only in how they transform the list before writing it back through the same undo record.
- A style's colour setter refuses an index the style does not have rather than clamping onto colour zero: the caller named a colour that is not there, and repainting a different one is worse than doing nothing. The stroke's position arrives from a slider as a float and rounds to the nearest real position rather than silently reverting to the default.
- **The filter stack was not a stack.** `LayerRenderPlan` resolved a layer's effects into one field per kind — `gaussian: f32`, `sharpen: Option<f32>`, and so on — and the GPU executor called a fixed helper per field in a fixed order. Three things went missing in that translation, none of them with a symptom: the user's ordering, because a sharpen stacked before a blur ran after it; repeats, because two blurs merged into the larger radius; and every kind without a field of its own, because a `_ => {}` arm absorbed Box Blur, Invert and Offset. Those three were creatable in the vocabulary, serializable in `.ptx`, and unrunnable. - **Zoom Blur, Unsharp Mask, High Pass, Clarity and Denoise.** The four that read a blurred copy alongside the source share one executor shape, declared by `blur_radius_input` rather than by each call site knowing which filters happen to be built on a blur. The Filter menu and the gallery picked all five up without a QML edit — the gallery had been naming five kinds explicitly and writing its parameter labels and ranges as nested conditionals on the combo index.

The uniform carries `MAX_ADJUSTMENT_SLOTS` (8) now, the projection is that array, and the chrome publishes one JSON list — a slot count is a property of the kind, and Invert has none while Levels has five. Slots also lost their `"p0"`/`"p1"` names: position in `editor_slots` *is* the index, so a parameter can no longer be described by one name and read from another. Collapsing the three inspector scalars into one slice made the badge-rule fixture exhaustive, so it dropped its `..default()` and now fails to compile when a rule is added without one.

Levels gained output black/white in the same pass, which is what the widened budget was for. All ten kinds are held to the engine reference by the device parity fixture.

Adding a kind to the engine put it straight into that arm. The mapping is `AdjustmentParams::gpu_op` now, one arm per variant so the compiler refuses a kind without a code, and a test refuses the value `0`. A `Repeater` over the engine's slot table replaces it; a kind with no parameters says so rather than showing an empty group. The engine's editor JSON carries label and order alongside the bounds, since the chrome now builds the control rather than looking up a bound for one it already drew.
- **The Layer menu ran off the bottom of the screen.** Thirty-one flat entries against a 1080p window, so its last items could not be clicked — and making the four dead adjustment kinds reachable would have added seven more. Action `menu` names are paths now: `parent.child` is a submenu, the shell declares each one and fills it from the registry, and a test fails if the engine names a submenu no menu instantiates. Shapes, boolean combines, layer styles, masks, locks and the adjustment kinds each moved one level down; the Layer menu is thirteen rows and fits.

The fixture found its own bug first: building the layer with `add_layer_top` then `set_adjustment` silently produced a blank raster layer, because that setter refuses a layer whose kind is not Adjustment.

They are non-separable: each mixes one attribute of the source with two of the backdrop, so a per-channel signature has no answer for them, and `blend_channel` returning the source was the only thing it could do. `blend_rgb` takes whole colours and is now the compositor's entry point, implementing the four through the standard `SetLum` / `SetSat` / `ClipColor` construction on Rec.601 luma — `ClipColor` scaling toward the colour's own luma rather than clamping per channel, since clamping would move the luminosity just set. - **`commands.rs` gave up its vocabulary and its tests, and kept its router.** At 3,688 lines it was the largest file left, and the obvious move — splitting the eighty-seven command bodies by family — turns out to be a bad trade: eighty-four of them are private, and sibling modules cannot call a private inherent method, so the split would mean widening all eighty-four to `pub(crate)`. That exchanges real encapsulation for shorter files. What moved instead is the half with no private surface: the identifiers, arguments, effects and errors, every item of which is already `pub`. Four `CommandEffects` constructors became `pub(super)`, which is the entire cost. The router and its command bodies stay together, which is also where they belong — the dispatch and the vocabulary it dispatches on are readable side by side. 2,555 lines.
- **The dock header wiring existed five times.** Each panel header restated the same ten lines: three enablement expressions derived from the panel's position in the stack, and three dispatches to `AppSession` that differ only by which panel id they name. `PanelHeaderControls` takes a `panelId` and its position now, derives the enablement once, and performs the move and auto-hide itself — those are the same action for every panel. Tear-off stays a signal, because where a floated panel lands is the shell's decision and genuinely differs per panel; that difference was the only thing distinguishing the five copies.
- **Canvas pointer input left the shell.** The last large block in `Main.qml`, and not only input routing: it owns the in-progress drag state the overlays draw from, which is why the gradient preview and brush cursor read it from the instance. The seam is ten shell helpers — the screen-to-document conversions and the five tool predicates, passed rather than re-derived, since duplicating either would be a second definition of where the pointer is or which tool is a selection tool — plus two signals for the context menus, which stay with the shell. `Main.qml` is 3,498 lines, from 6,621 at the start of these slices.
- **`CommandScope` and `MutationClass` were declared for all seventy-nine commands and read by nothing.** The command spine itself turned out to be in good order — every id is registered, routed and carries metadata, and a test already checks it — but the taxonomy describing what each command *touches* had no consumer. The rule it exists to state, that view and workspace commands leave the document alone, was verified by invoking three hand-picked commands; twelve claim that scope, so nine were asserting nothing. This is the shape that let `UndoPolicy::Mergeable` sit unimplemented. The check now iterates the taxonomy, so marking a command ephemeral is a claim the suite tests rather than a comment — mislabelling `layer.create` fails it by name. Every command whose declaration exempts it must also appear in the argument table, so adding one cannot quietly opt out of the check.
- **Half the chrome icon buttons ignored the type built for them.** `ChromeIconToolButton` exists to state the house style for icon-only buttons on dark chrome once; the toolbar used it six times while five panel-header buttons hand-rolled the same thirty-three lines each — icon-only display, a `ThemedIcon` content item, a hover background. They had already drifted: the hand-rolled ones use a tighter corner radius, and, unlike the shared type, they suppressed the hover background when disabled. That guard was the better behaviour, so it moved into the type rather than being lost; a disabled button no longer lights up anywhere. About a hundred and thirty lines of restatement gone.
- **The layers list left the shell; the dock as a whole did not.** Measuring first is what decided it: the dock's `GridLayout` crosses its boundary thirty-three times — twenty-seven distinct `root.*` references plus ids in both directions — and a component with thirty-three declared dependencies is the same code with a long parameter list, not a decoupled one. Its individual panel bodies are a different matter, and the layers list is the narrowest: two values in, one signal out, for about a hundred and ninety lines. It became extractable only after the panel gained a real model, since the delegate had been reaching into six shell-scoped arrays. The dock placement stays behind, and the context menu is now a signal rather than a reach for the shell's `Menu`. `Main.qml` is 4,015 lines.
- **Twenty-four of twenty-eight GPU entry points ran without checking whether the device was still alive.** Every function in `document_gpu.rs` opens the same way — shared queue lock, document mutex, a document to actually be open, and the device not lost — and the fourth step was written by hand in four of them. The rest would issue GPU work against a lost device and surface whatever wgpu said instead of the app's recovery path. `with_document` takes the body as a closure, so the check cannot be left out; a source-level test names the three exceptions (the two that install the context and the one that tears it down) rather than inferring them.
- **That sweep nearly turned device-loss recovery into data loss.** Recovery takes a best-effort pixel snapshot before rebuilding, because a soft loss often still permits readback — so making `read_all_layer_rgba` refuse while the flag is set would have rebuilt every recovered document with blank layers. It now goes through a named `with_document_despite_loss`, and the recovery test asserts the readback is attempted rather than refused, so the next "check everywhere" sweep fails loudly instead of silently discarding pixels. The existing comment on that call is what caught it.
- **Mask feather works, and finding out why it did not turned up a blur that only ever blurred one way.** The control shipped disabled because the composite samples masks from an R8 array and the separable blur was RGBA-only — but the blur's fragment stage was always format-agnostic, so only the pipeline's colour target and its two scratch textures pinned it to RGBA. Those are a parameter now. Feather runs where it has to: softening a texel needs its neighbours, so the mask is blurred before it is packed, and the shader still applies invert, contrast, shift and density per sample — which is what `LayerMask::coverage` describes and `LayerMask::feathered` now names as the other half. Wiring it up produced a mask that came back unchanged, and the cause was not the new code: `SeparableBlur` held one uniform buffer and rewrote it per pass through `Queue::write_buffer`, whose writes are staged until submit, so every pass recorded into an encoder read whichever direction was written last. The separable blur has only ever run along one axis, and two blur calls in a frame shared one radius. Each pass owns its uniform now. Two device tests pin it from both sides — a one-texel-tall document, where only a horizontal pass can soften, and a one-texel-wide one for the vertical.
- **`phototux_io`'s byte readers agree on how to fail.** Nine of them answered the same question — take the next N bytes, or fail because there are not N left — written out once per width and per access style. They did not agree: `read_slice` in `ptx.rs` bounded its arithmetic with `checked_add` while the two fixed-width readers beside it added unchecked, and `psd.rs` reported a truncated read as `BadSignature`, which would tell someone their valid-but-short PSD was not a PSD. Neither was reachable today — the ptx offsets are bounded by construction and the PSD header is length-checked before those reads happen — so this is a latent hole closed and a wrong error corrected, not a bug fixed. One const-generic reader per crate now carries the endianness, the overflow guard and the error, and five tests pin them, including that a failed read leaves the cursor where it was.
- **Clipboard payloads validate themselves, and one of them was not being validated at all.** All three channels travelled as bare `(u32, u32, Vec<u8>)` tuples, which promise nothing about the buffer matching the dimensions beside it, so every site had to remember to check — and they disagreed. Copying a layer mask checked only the 64 MiB ceiling where its selection-mask sibling also checked that the buffer described the open document; pasting an image discarded the dimensions outright, with a `let _ = (width, height);` marking the spot. Nothing was corrupted, because the GPU rejects a mismatched upload — but it rejects it *after* the paste command has committed a layer, so the user got an empty "Pasted" layer and a texture error instead of a refusal. `ImagePayload` and `CoveragePayload` ask the question once, in their constructors, and the raw checks are now private so no caller can answer it differently. Paste checks `fits(document)`, which is the one remaining question, before the command runs. Nine call sites, eight new tests.
- **The layers panel reads a list model instead of six index-aligned strings.** Names, visibility, kinds, mask flags, clipping and selection each crossed to QML as a pipe-joined string, were `split("|")` into six JavaScript arrays, and were indexed by hand in every delegate — after inverting the row number, because the strings ran bottom→top while the panel draws top→bottom. Nothing enforced that the six agreed, and a delegate reading past the end of one got a default that looked like real data: a visible, unselected, unmasked raster layer. `phototux_engine::layer_rows` now builds one row per layer, already in display order and carrying its own engine index, so no QML arithmetic inverts anything; `phototux_ui::layer_model` wraps them as a `QListModel`. Renaming a layer repaints one line rather than rebuilding all six strings and re-announcing them. Three "active layer's X" properties that QML derived by indexing those strings are scalars on the session now — the shell only ever wanted one layer's value. Eighteen headless tests, including that every field counts as a change and that role names are the ones the delegate binds.
- **The history panel followed, and lost a workaround on the way.** Labels, kinds and entry ids were three more index-aligned strings, and the id list is the one with consequences: clicking a row hands its id straight to `jumpHistoryEntry`, so a row whose label had caught up but whose id had not would move the document somewhere the user did not click. `HistoryService::rows_newest_first` walks the timeline once instead of three times, and the kind names moved onto `HistoryKind::as_str` where they belong. The special case this removes is worth naming: a stroke pushes a history entry but reports no layer sync, so the panel used to omit every brush stroke until an unrelated edit refreshed it — patched by stashing the previous id string and comparing it after each sync. The model decides for itself what moved, so that comparison, and the three hand-written notify triples around it, are gone.
- **Item models turn out to be the synchronous half of the host re-entrancy rule.** A property notification may be re-evaluated after the slot returns, which is why reading host state from a binding is normally safe. A model's row change is delivered to its view *during* the notification, so a delegate binding that reads the host re-enters a session that is still borrowed and aborts the process. The layers panel hit it twice: once through a `maskEditActive` binding and once through the icon helper, which resolved its asset root from the host — a binding read hiding inside a function call. Both are cached on the shell root now, and the contract is written down in handbook 32 and `qml/AGENTS.md` rather than left to be rediscovered by the next model.
- **The other half of that pairing is now done too.** `sync_from_engine` assigned about fifty fields and `emit_layer_fields` announced forty-two of them — two hand-maintained lists, hundreds of lines apart, with nothing tying an entry in one to an entry in the other. Thirty-three fields now publish where they are computed, leaving thirteen blind announcements for the properties that are computed getters rather than stored state and so have nothing to compare against. The effect is on a hot path: slider drags reach the host through the command spine, so dragging opacity fired all forty-two notifies per pointer sample, waking every binding on every one of them. The nine fields that were assigned in both arms of an `if let … else` now read their value as one tuple, which also puts the no-mask defaults — what the panel shows for an unmasked layer — in one place beside the real ones. A source-level conformance test fails if a field ever publishes conditionally *and* announces unconditionally, since that combination silently buys nothing while looking like a guard.
- Twelve slots each stored the engine's latest announcement and emitted its notify as a hand-written pair. `publish_announcement` pairs them, so an announcement cannot be stored without being published — the failure that leaves a screen reader describing the previous action.
- **Durable file replacement has one implementation.** `phototux_io` wrote the same sequence twice — unique sibling, write, `sync_all`, rename, remove the temporary on failure — character-for-character identical between raster export and `.ptx` apart from the error type and one message, backed by two independent sequence counters that only avoided colliding because the file names differed. `atomic::write_atomic` owns it, generic over the caller's error type.
- **Autosave's index file was not written atomically.** The `.ptx` snapshot went through the atomic path; the JSON index beside it, which the restore chooser actually reads, used a plain `fs::write`. A crash midway through left a truncated index that made a perfectly good snapshot unlistable. It now uses the same path as everything else.
- **Which document features become which render passes moved into the engine.** `LayerPackPlan::from_layer` was 90 lines of pure Rust in `phototux_gpu` deciding that a blur effect or a shadow style earns a pass, which wins when two overlap, and what is too small to bother with — document policy in the crate that knows how to *run* a pass, not which passes a layer deserves. `phototux_engine::LayerRenderPlan` owns it now, with eight headless tests; the GPU crate keeps the descriptor-to-pipeline half and re-exports the type so call sites are unchanged. `effect_pass.rs` previously had no test coverage at all.
- That move surfaced a policy defect in daylight: a layer carrying both a drop shadow and an outer glow silently loses the glow, because both are expressed through one `drop_shadow` slot. The behaviour is unchanged for now, but it is documented at the function, pinned by a test so a fix fails loudly there first, and ranked in the gap analysis — fixing it needs a second shadow pass in the renderer, so it is not local to the plan.
- **The GPU crate stated its own conventions five times.** Every full-screen pass needs the same vertex stage, the same render-target usage flags and — for the stampers — the same scissor planning, and each pass wrote them out again: five byte-identical vertex shaders, three copies of the render-target constructor differing only in the order of the same four flags, and two copies of the dab batch planner. `pass.rs` holds one of each. A wgpu descriptor change, or adding a timestamp query to every pass, is now one edit rather than five, and the off-canvas dab rule — where an empty scissor is invalid, not merely wasteful — has one statement instead of one per stamper.
- **`LazyDialog` never loaded anything, and the command palette never opened.** The type wraps a `Loader`, whose default property is `data` rather than `sourceComponent`, so a dialog written inside `LazyDialog { … }` became an ordinary child object: nothing was ever loaded and `item` was null forever. Dialogs whose visibility is bound to host state still worked — they existed as eager children — which hid the fault and also meant the deferred construction this type exists for never actually happened. The palette, which reaches its API through `ensure()`, received null and failed silently. `LazyDialog` now declares `default property Component dialog` and binds `sourceComponent` to it; call sites are unchanged (T-034).
- **`statusText` stopped doubling as an RPC channel to QML.** Ten `"host:…"` magic strings were written into the status-bar property and prefix-matched in QML — a contract duplicated across two languages that nothing checked, where a typo was a silently dead menu item, and where `setStatus` let any QML caller forge one. `phototux_engine::HostRequest` names the vocabulary once with round-trip and distinctness tests, and a dedicated `pendingHostRequest` property carries it, so the status bar is only status again.
- **Shape rasterization moved into the engine.** `shape_pixels` sat on the qtbridge `AppSession`, calling only engine functions and touching neither Qt nor the GPU — engine work that happened to live in the toolkit crate, where DR-022 says core logic must not be, because a `#[qobject]` cannot be constructed in a unit test. `phototux_engine::rasterize_shape_content` replaces it, with `rgba_f32_to_u8` replacing six near-identical inlined clamps in the same function. Six headless tests cover fill, the empty case, the gradient path, boolean subtract, gamut clamping and dimension overflow.
- **PSD flattened export composited every layer as Normal.** `phototux_io` kept its own compositor that bound the blend mode as `_blend` and ignored it, so exporting a document with Multiply, Screen or Overlay silently lost them. It now delegates to `phototux_engine::composite_rgba8` — the crate already depended on the engine, so the third implementation was never needed.
- **Colour dodge and colour burn rendered wrong on the GPU.** WGSL's `select(f, t, cond)` returns `t` when the condition holds; the shader had both arms reversed, so dodge returned white for every source below 1.0 and burn returned black for every source above 0.0. The CPU reference did not catch it because it implemented neither mode — seven of seventeen fell through to a `_ => s` arm — and the parity fixture compared three modes.
- The CPU reference now covers every mode the shader genuinely computes, `PARITY_BLEND_MODES` lists all twelve rather than three, and hue/saturation/colour/luminosity are documented as a shared fallback rather than silently missing.
- **Layer styles were not undoable, and undoing a vector mask consumed a step without removing it.** Recording an edit in history was a convention each command restated rather than a step it could not skip, so five commands bumped the document generation and recorded nothing — while `command_meta` declared all five `UndoPolicy::Transaction`. Drop shadow, stroke, outer glow and colour overlay now share one `add_layer_style` and record a `SetStyles` edit; `mask.create-vector` records a real `SetVectorMask` instead of a `Transform` entry, which `undo_next` hands to the host as a no-op. `record_graph_edit` owns the tail — bump, record, produce effects — so the three cannot come apart again.
- The conformance suite now checks behaviour rather than table shape: each style command must round-trip through undo, creating a vector mask must round-trip, and — generically — a command that moves the document generation must leave an undo entry behind. All three fail against the previous code, verified by reverting.
- **Apply Layer Mask ignored the mask's contrast and shift.** Mask semantics had no owning definition: the composite shader applied invert → contrast/shift → density, while the bake path in the UI crate open-coded invert → density and dropped the middle step, so baking a mask with either refine set produced pixels that did not match the canvas. `LayerMask::coverage` is now the single definition, next to the type that declares the fields, with the ordering documented and six headless tests over it — including that refine pivots on 0.5 and that coverage stays in range across the extremes of all three controls.
- `LayerMask::feather` is recorded as a gap rather than quietly implemented or deleted: it is stored, clamped, undone and bound to QML while affecting no pixel anywhere, and unlike the other controls it is a neighbourhood operation that `coverage` cannot express per sample.
- **Undo after Mask → Selection was a no-op.** Thirteen slots hand-rolled the same GPU-edit protocol — snapshot the pre-state, copy layer metadata for the GPU, run the op, publish the composite time *and* the repaint, record the command, map the error — in an order that was load-bearing and written down nowhere. Twelve snapshotted before mutating; `apply_mask_to_selection_host` snapshotted after, so it stored the state the undo was supposed to reverse. `commit_selection_edit` and `commit_layer_edit` own the protocol, and `push_selection_snapshot` / `push_transform_snapshot` are now reachable only from inside them, so the ordering cannot be restated wrongly at a call site (T-033).
- **Hiding the raised tab of a dock group hid its siblings too.** The dock topology records which tab the user last raised, but visibility lives in `WorkspaceState`, so the stored selection was used even after it was hidden and no sibling qualified to draw. `effective_active_tab` falls through to the first visible tab, and returns `None` only when the group has genuinely nothing left to show (T-032).
- Seven workspace slots repeated the same failure epilogue verbatim (format a message, emit `statusText`, return early, else persist). One `commit_workspace_op` owns it, so "a rejected layout change must not be persisted" is a property of the operation rather than a convention each slot restates.

## [reentrancy-and-contrast] — 2026-08-13

### Fixes

## [paint-fluidity-3] — 2026-08-12

Canvas fluidity pass, part three: stop paying whole-canvas cost for small dabs.

### Rendering

- **A dab batch is one scissored render pass, not a pass per dab.** Each dab began its own `begin_render_pass` over the entire layer and drew a full-screen triangle whose off-dab fragments were discarded — on a 4K layer a 20 px dab rasterized 8.3 M fragments to keep about 1 250, and consecutive dabs paid a pipeline drain plus a full attachment load and store between them. The batch now records one pass and scissors each dab to the region it can touch. Draws within a pass blend in submission order, so the result is unchanged. Dabs entirely off-canvas are skipped, since an empty scissor rect is invalid.
- Pipeline switches are now only rebound when the paint/erase mode actually changes within a batch.
- Mask painting uses the same batched, scissored path, sharing the bounding helper rather than repeating it.
- **The composite re-blends only the region painted since the last one.** It was unconditionally whole-canvas, all layers, with `LoadOp::Clear` and no scissor, and the layer-array slice copy moved the entire layer — 33 MB at 4K — per composite. The engine now accumulates the painted region and bounds both the blend and the copy to it. Gated on a complete previous result, no structural repack, every invalidation carrying a region, and byte-identical layer parameters; failing any of those falls back to the full path, so the worst case is the cost it had before rather than a stale canvas. Effect layers still copy whole, since a blur changes output beyond the pixels that fed it.
- **The canvas repaints when content changes, not every vsync.** `FrameAnimation` wrote `phase` each frame and `setPhase` called `update()`, forcing a full RHI sync and render pass forever — but the shader reads `phase` only after an early-out on selection ants, which are almost always off. A new `contentTick` property, driven by a `compositeGeneration` counter the host bumps on every published composite, now schedules the repaint. `synchronize()` is also where the pending export is pulled from Rust, so the tick had to be the invalidation signal or the canvas would have frozen instead of idling.
- **Stroke undo is bounded by VRAM, not by entry count.** Each backup is a full copy of the painted surface, so the cap of 64 entries meant a few megabytes on a small document and over 2 GB at 4K — allocator pressure and eviction hitches long before the count was reached. A 512 MB budget now sets the depth, and the most recent stroke is always kept even if it alone exceeds it.
- **Mask strokes no longer end with a blocking full-mask readback.** `end_stroke` downloaded the whole mask — 8.3 MB at 4K — and blocked on GPU completion, holding both the shared queue guard and the document lock, at every mask pen-up. It was redundant: every consumer of the CPU mirror already refreshed it before reading. `read_mask_r8` now performs the sync itself, so the cost lands on the slow path that wants the bytes and a caller cannot forget it.
- Marching-ants `dashOffset` bindings no longer re-evaluate every frame when no selection exists; bindings on children of an invisible item still run, so the parent's visibility gate was not enough.
- `last_composite_bounded()` exposes which path ran, so a test comparing bounded against full cannot pass by never taking the bounded path — `write_layer_rgba` marks the array structurally dirty and had been doing exactly that.

### Tests

- Nothing in the suite read pixels back after stamping, so the previous 42 GPU tests could not have observed a scissor that clipped strokes. Four device-backed tests now cover full-radius coverage, every dab of a batch landing, edge clamping, and the off-canvas case; `a_stamped_dab_covers_its_whole_radius` is verified to fail against a deliberately tight bound.

## [paint-fluidity-2] — 2026-08-12

Canvas fluidity pass, part two: make the brush respond to pressure. This half is
the engine; it lands first so that wiring a stylus cannot regress anything.

### Brush engine

- **Spacing follows the diameter being stamped.** `spacing()` used the nominal brush size while the radius came from pressure, so with `size_pressure` on (the default) a light touch drew dabs a fraction of the nominal width and spaced them at the full width — at pressure 0.2 that is a 1.25-diameter gap between dabs, a dotted line rather than a thin one. Spacing is now `spacing_at(pressure)`, re-evaluated as the segment is walked, which is the handbook's integrated local spacing. A brush with `size_pressure` off is unaffected.
- **Pressure ramps across a segment.** `move_to` applied the arriving sample's pressure to every dab between it and the previous sample, so a smooth press produced one visible step per input event and the step count tracked the input rate. Pressure now interpolates between the two samples, and spacing tightens with it.
- Constant-pressure strokes — every mouse stroke until stylus input is wired — place dabs at exactly the same positions as before, pinned by `constant_pressure_spacing_is_unchanged`.

### Input

- **Stylus pressure reaches the brush.** Both stroke calls read `mouse.pressure` off `QQuickMouseEvent`, which has no such property — the check `typeof mouse.pressure === "number"` was always false, so every dab of every stroke was stamped at 1.0 and the engine's pressure dynamics never received a signal. Pressure now comes from a `PointHandler` tracking the same point, which exposes the device's real value. It takes only a passive grab, so the `MouseArea` keeps owning every gesture. Devices without pressure report 0 while held and fall back to full pressure, so a mouse behaves exactly as before.
- **Not verified on hardware.** No stylus is attached to the development machine and synthetic pointer input cannot be delivered on this session, so the handler is confirmed to instantiate without QML errors and to be a safe superset of the previous behaviour by construction — but nobody has yet drawn a pressure-varying stroke. Worth ten seconds with a tablet before relying on it.

## [paint-fluidity-1] — 2026-08-12

Canvas fluidity pass, part one: remove work from the stroke path that the display
never shows and the user always waits for.

### Rendering

- **The interactive composite no longer blocks on GPU completion.** `repack_array_if_needed` ended its submission with `PollType::wait_indefinitely`, and every mid-stroke composite reaches it: `stamp_dabs` marks the painted layer, which puts a dirty slice in the repack, and the early-out requires that list to be empty. Measured on Arc B580 / Mesa 26.1 at 10 layers × 4K: **1.94 ms → 0.57 ms** of host time per composite, held under the shared queue lock the Qt render thread needs.
- DR-030 already forbade this; the wait survived because the guard test could not see it. `interactive_composite_does_not_wait_for_the_gpu` never marked a layer painted, so it only ever measured the clean path, which skips repacking altogether. The test now paints, runs at the DR-017 gate size, and compares the fastest call rather than the mean — sustained submission hits backpressure, where wall time converges to GPU throughput whether or not the host waits, and the mean stops discriminating. Verified to fail at 1.94 ms against the old behaviour and pass at 0.57 ms with the fix.
- **Mid-stroke composites are paced against time, not dab count.** The trigger was `dabs_since_composite >= 4`; dab rate is pointer speed over spacing, so it tracked how fast you moved rather than the refresh rate. One constant failed in both directions — a size-4 brush at 1000 doc px/s asked for ~250 composites/s against 60 displayed frames, while a size-200 brush at 100 px/s went 2 s between composites with the stroke stamped but invisible. Now paced at 8 ms, which admits 120 Hz without firing twice per frame at 60 Hz. The worker waits on that gap when dabs are pending, so a stroke that pauses mid-air still lands its tail.
- **Stroke end composited twice.** The tail flush asked for a composite and `end_stroke` composited again immediately after; the flush no longer does.

### Shell

- **The action table is built once instead of per lookup.** `action_by_id` called `default_actions()`, which allocates ~800 strings across 101 descriptors, then linearly scanned the result — so a single "can I undo?" question constructed the whole table. Around 100 menu items bind to enablement and all of them re-evaluate together whenever an enablement input changes, which includes every pen-up. The table is now a `LazyLock` with an id index, and `action_by_id` borrows from it. `default_shortcut_map` / `default_action_shortcuts`, on the shortcut path, borrow it too.
- **Per-frame and per-composite property signals are guarded.** `fps` signalled on every frame from a smoothed float whose rounded readout rarely moved; `compositeMs` signalled on every paced composite throughout a stroke at a precision finer than its two-decimal readout. Both relaid out the status bar — and `compositeMs` the collapsed Diagnostics summary — for values that had not visibly changed. Both now emit only when the displayed value would differ. `can_undo` / `can_redo` / `dirty` at pen-up are guarded the same way, since ~100 enablement bindings re-evaluate together on them.

### Fixes

- **The stroke journal no longer writes to disk on the UI thread.** `StrokeJournaled` arrives in the frame tick at pen-up, and its handler did `create_dir_all` plus `fs::write` of a pretty-printed record of every sample and dab — a few hundred KB for a long stroke — synchronously, in the frame the user is watching. It now goes to the existing `FileWorker`, and the record serializes compactly since only recovery reads it.
- **The History panel omitted brush strokes.** A stroke pushes a history entry, but `raster.paint-stroke` reports no layer sync, so `emit_layer_fields` — the only emitter of `historyLabels` / `historyEntryIds` / `historyKinds` — never ran for it, and `emit_poll_dirty_changes` did not emit them either. The panel silently stayed stale until some unrelated edit refreshed it. Now emitted whenever the entry list changes.

## [prefs-missing-key-defaults] — 2026-08-12

### Fixes

- **A preferences file missing the legacy panel keys started with every right-dock panel hidden.** `Preferences` carries a container-level `#[serde(default)]`, which resolves missing keys against the product default — but the five legacy `panel_*` bools each also carried a *field-level* `#[serde(default)]`, and the field-level attribute wins. Those resolved to `false`, `migrate_panel_visibility()` then filled `panel_visibility` from them, and the shell came up with a blank dock. The redundant attributes are removed, so an absent key now means "not recorded" rather than "the user hid it".
- Same removal on `high_contrast`, `reduced_motion`, and `safe_start_next`, where the two defaults already agreed. This is a no-op by itself, and it is what makes the remaining attributes legible: every field-level `#[serde(default)]` left on the struct now marks a field whose emptiness is a **load-bearing sentinel** — `panel_visibility` (triggers migration), `dock_topology_json`, `brush_presets_json`, `user_workspace_presets_json`, `last_saved_workspace_json` (trigger backfill or normalization), and `disclosure_open` (sparse by contract). Each says so in its doc comment.

Not reachable from any file the app itself writes, since those always serialize `panel_visibility`. Found by hand-authoring a minimal file for a screenshot harness.

### Tests

- `sparse_file_keeps_product_panel_defaults` deserializes `{"schema_version": 7}` and asserts the essentials panels survive migration; verified to fail against the old attributes.
- `legacy_file_still_migrates_its_own_choices` pins the other half — an absent `panel_visibility` must keep resolving to empty, or a genuine schema-2 file would skip migration and lose the user's recorded choices.
- `sparse_file_preserves_backfill_sentinels` covers the remaining sentinel fields.

## [inspector-badges-and-visual-pass] — 2026-08-12

Closes the loose ends left by `[inspector-disclosure]`, and gives the density work its first
verification on a real display.

### UX

- **Header badges are derived from host state.** `inspector_badges()` computes a group id → `{text, severity}` map from an inspector state snapshot, published as `inspectorBadgesJson`; `DisclosureGroup` resolves its own badge by id. Handbook 28 requires an invalid value to reach a collapsed header without the body existing, so the rule cannot live in the widgets that own the value. Shipped rules: an adjustment parameter outside the editor's range, an active selection whose outline misses the canvas, a text layer whose font family is not installed, and GPU loss.
- **Adjustment editor ranges are a registered contract.** `adjustment_editor_ranges()` is read by both the sliders and the out-of-range rule, so the two cannot disagree about what is showable. Editor bounds stay narrower than the engine's accepted bounds: a document may legally carry a gamma the slider cannot reach, and that now raises a badge instead of silently pinning the control.
- **All ten groups carry a collapsed summary**, up from three — the parameter worth confirming before expanding. Where a badge and a summary compete for header width the summary elides first, and the badge elides against a bounded share rather than widening the row.
- **Expand-all / collapse-all are wired.** Registered as `action.view.expand-all-groups` / `action.view.collapse-all-groups` for menu and action-search discovery, and surfaced as a state-reflecting control on the Properties header — offering collapse while any group is expanded, expand otherwise. The `AppSession` slots that had no caller are now the header's handler.

### Fixes

- **Panel-header drag areas swallowed button clicks at `comfortable` density.** All five headers reserved a literal 110 px for chrome, but four buttons already span 112 px at that density. Each header now measures its own `PanelHeaderControls`. The Properties reserve for the panels stacked below it moves from a literal to `Theme.dockStackReserve` for the same reason.
- **Collapsed groups pointed the caret up**, contradicting the Right-expands / Left-collapses grammar on the same header. Collapsed now points right.
- **`inspector.brush` was laid out ninth though the registry declares it second.** Handbook 28 forbids reordering registered groups; `inspector_lays_groups_out_in_registry_order` now asserts the layout against the registry, since a declarative layout offers nothing else to assert against.

### Verification

- First visual pass on a real Wayland session: dense, `comfortable`, and `QT_SCALE_FACTOR=2`, plus a forced-visibility QML override that puts all ten group headers on screen at once. Density confirmed to drive layout, not only type.
- Known limits recorded rather than papered over: the right dock still gives Layers and History header-only height in a ~900 px window and at 200 % scale, and the missing-font badge stays silent until fontconfig discovery has run. Both are ranked in the gap-analysis backlog.
- Pointer clicks could not be injected on this session (KWin ignores `ydotool` uinput events), so the header control's two states were verified by seeding `disclosure_open` both ways rather than by pressing the button.

## [composite-no-host-wait] — 2026-08-12

### Decisions

- **DR-030** — zero-copy present is ordered by a shared-queue image memory barrier, not a host wait. Qt adopts wgpu's device *and* queue, so a barrier before submit applies to Qt's later frame in submission order.
- **DR-031** — GPU budgets are measured with timestamp queries, collected asynchronously; benchmarks use a separate entry point that waits.

### Rendering

- `composite()` no longer blocks on `device.poll(wait_indefinitely())`. Measured: host 0.05 ms vs 0.20–0.30 ms GPU for the same pass; `recomposite()` runs on the UI thread, where handbook 28 forbids waiting for GPU completion.
- Stroke path no longer stalls on every fourth dab; wgpu's own tracking supplies the stamp→composite barrier.
- Readback, sampling, and export paths still wait, as they must — they map GPU memory to host memory.
- `SharedQueueGuard` retained: `vkQueueSubmit` needs external synchronization regardless of GPU ordering.

### Measurement

- `compositeMs` is now GPU time from `TIMESTAMP_QUERY` (one composite behind), replacing host wall time around the removed stall. 10×4K gate: **1.79 ms GPU**.
- Devices without timestamp queries report "no GPU timing" rather than 0 ms.
- Stroke latency relabeled input→submit; end-to-end input→present stays Provisional pending present-side instrumentation.
- New `interactive_composite_does_not_wait_for_the_gpu` fails if a blocking wait returns to the interactive path.
