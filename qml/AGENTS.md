# qml/

Qt Quick shell. Tokens come from `Theme.qml` and handbook [25 — Themes](../internal_docs/25-Themes.md).

- Dense editor chrome. Canvas-first. No second palette or spacing scale.
- Icons: `assets/icons/phosphor/` via [`assets/icons/ICON_MAP.md`](../assets/icons/ICON_MAP.md).
- `import phototux_ui` for `AppSession`. `qmllint` unresolved-import on that module is expected.
- User-facing strings: `qsTr(...)`.
- **Never call an `AppSession` slot synchronously from a handler that reacts to an `AppSession` signal** — `Connections`, binding-driven `on…Changed`, focus/popup callbacks, anything a `Loader` builds from host state. The slot that emitted still holds the session borrowed, so a re-entrant call aborts the process. Route it through `root.afterHostSlot(fn)`. Direct calls from user input (`onClicked`, `Keys.on…`) are fine. Handbook [32 — Host Slot Re-entrancy](../internal_docs/32-Developer-Guide.md#host-slot-re-entrancy).
- **Never read `AppSession` from a binding inside a model-driven delegate** — take per-row values as model roles and anything else from a `root` property. A model's row change reaches its view *synchronously*, inside the host slot that made it, so a delegate binding that reads the host re-enters it and aborts. This includes helper functions called from a binding: `root.iconUrl(...)` reads `AppSession.iconRoot`, which is why that read is cached on `root`. Click handlers are fine. Handbook [32 — Item models are the synchronous case](../internal_docs/32-Developer-Guide.md#item-models-are-the-synchronous-case).
- No Controls style is configured, so the shell runs the **Basic** style, which hardcodes a light palette and ignores `palette`. Use `ThemedButton` / `ThemedCheckBox` / `ThemedComboBox` / `ThemedSpinBox` / `ThemedDialogHeader` rather than the bare controls, and theme any new one you reach for. `no_unstyled_controls_reach_the_user` fails the build on a bare one.
- **Size a layout child with `implicitWidth` / `implicitHeight`, never `width` / `height` / `anchors`** — the layout owns its children's geometry and Qt leaves the conflict undefined. Use `Layout.preferredWidth` when the value only makes sense inside a layout. Likewise, never name a property after one the base type has (`Item.scale`): `qmllint`'s `layout-positioning` and `property-override` must both stay at zero. Handbook [32 — QML module and shared components](../internal_docs/32-Developer-Guide.md#qml-module-and-shared-components).
